# 飞马星球医院预约挂号系统 - 开发说明文档

本文档旨在为开发者（特别是初学者）提供一份详尽的项目指南。我们将从项目架构、技术栈、文件结构到具体代码功能进行全方位的解析。为了方便理解，每个部分都提供了**专业解释**和**通俗解释**。

---

## 1. 项目简介

这是一个基于 Java Web 技术栈开发的医院预约挂号系统。系统分为**前台患者端**和**后台管理端**，涵盖了从用户注册、医生排班、在线预约到报表统计的完整业务流程。

- **专业解释**：本项目采用标准的 MVC (Model-View-Controller) 架构模式，基于 Jakarta EE 10 规范（Servlet 6.0 + JSP 3.1），使用 Maven 进行依赖管理和构建。数据持久层采用 JDBC 原生实现，前端使用 JSP + JSTL + EL 表达式进行渲染。
- **通俗解释**：这就好比一家餐厅。
    - **JSP (View)** 是服务员，负责把做好的菜（数据）端给客人（用户）看。
    - **Servlet (Controller)** 是前台经理，负责接收客人的点单（请求），然后指挥后厨去做。
    - **Service/DAO (Model)** 是后厨，负责切菜、炒菜（处理业务逻辑和读写数据库）。
    - **MySQL** 是大冰箱，所有的食材（数据）都存在这里。

### 3.2 Java 源代码 (`src/main/java/com/pegasus/hospital/`)

这是后端代码的核心区域，按照功能分成了不同的包（Package）。

#### 3.2.1 实体层 (`entity/`)
**作用**：定义与数据库表对应的 Java 类（POJO）。

| 文件 | 解释 |
| :--- | :--- |
| `Patient.java` | **患者实体**。对应数据库的 `patient` 表。包含姓名、手机号、余额等属性。 |
| `Doctor.java` | **医生实体**。对应 `doctor` 表。包含医生姓名、职称、所属科室等。 |
| `Admin.java` | **管理员实体**。对应 `admin` 表。包含管理员账号、密码等。 |
| `Schedule.java` | **排班实体**。对应 `schedule` 表。记录哪个医生在什么时间段有空，还能挂多少号。 |
| `Appointment.java` | **预约记录实体**。对应 `appointment` 表。记录谁（患者）在什么时候预约了谁（医生）。 |
| `Department.java` | **科室实体**。对应 `department` 表。如“内科”、“外科”。 |

#### 3.2.2 数据访问层 (`dao/`)
**作用**：Data Access Object。直接与数据库打交道，执行 SQL 语句。

| 文件 | 专业解释 | 通俗解释 |
| :--- | :--- | :--- |
| `DBUtil.java` (在 util 包) | 数据库连接工具类，使用 HikariCP 连接池管理 Connection。 | 它是“连接池管理员”。每次 DAO 想去数据库拿数据，都要找它借一条“电话线”（连接）。用完了再还给它，不用每次都重新拉线。 |
| `PatientDAO.java` | 封装了对 `patient` 表的 CRUD（增删改查）操作。 | 专门负责管理患者档案的管理员。你要找个患者、改个名字、充个值，都得通过他去翻档案柜（数据库）。 |
| `DoctorDAO.java` | 封装了对 `doctor` 表的操作。 | 专门管理医生档案的管理员。 |
| `ScheduleDAO.java` | 封装了对 `schedule` 表的操作。 | 专门管理排班表的管理员。 |
| `AppointmentDAO.java` | 封装了对 `appointment` 表的操作。 | 专门管理预约记录本的管理员。 |
| `AdminDAO.java` | 封装了对 `admin` 表的操作。 | 专门管理管理员账号的管理员。 |

#### 3.2.3 业务逻辑层 (`service/`)
**作用**：处理具体的业务规则，调用 DAO 层。

| 文件 | 专业解释 | 通俗解释 |
| :--- | :--- | :--- |
| `PatientService.java` | 处理患者相关的业务逻辑，如注册校验、登录验证、余额充值等。 | 患者的“私人管家”。比如你要注册，他会先检查你身份证对不对（业务逻辑），确认没问题了，再叫 `PatientDAO` 把你记下来。 |
| `DoctorService.java` | 处理医生和排班相关的业务。 | 医生的“经纪人”。负责安排医生的工作时间，查询医生信息。 |
| `AppointmentService.java` | 处理预约核心逻辑。如：检查是否重复预约、扣减号源、生成预约单。 | 挂号处的“办事员”。你来挂号，他得先看医生还有没有号（逻辑判断），如果有，就给你开单子（调用 DAO 写入），并告诉医生号少了一个。 |
| `AdminService.java` | 处理管理员登录等业务。 | 管理员的“助手”。 |

#### 3.2.4 控制层 (`servlet/`)
**作用**：接收 HTTP 请求，调用 Service 层，决定跳转到哪个 JSP 页面。

| 文件 | 专业解释 | 通俗解释 |
| :--- | :--- | :--- |
| `LoginServlet.java` | 处理 `/login` 请求。判断是患者还是管理员登录，验证成功后将用户信息存入 Session。 | 医院大门的“门卫”。你出示证件（账号密码），他核对一下，对的话就放你进去，并给你发个临时通行证（Session）。 |
| `RegisterServlet.java` | 处理 `/register` 请求。接收表单数据，调用 Service 完成注册。 | “注册窗口”。接收你填的表格，帮你办理入院手续。 |
| `PatientServlet.java` | 处理 `/patient` 路径下的请求。如查看个人中心、充值等。 | 患者服务中心的“接待员”。专门处理已经进来的患者的各种需求。 |
| `DoctorServlet.java` | 处理 `/doctor` 路径下的请求。如查询医生列表、医生详情。 | 导医台。你想找医生，就问他。 |
| `AppointmentServlet.java` | 处理 `/appointment` 路径下的请求。如发起预约、取消预约。 | 挂号窗口。专门处理挂号和退号的事宜。 |
| `AdminServlet.java` | 处理 `/admin` 路径下的请求。后台管理的所有功能入口。 | 院长办公室的“秘书”。处理后台所有的管理事务。 |

#### 3.2.5 工具类 (`util/`)
**作用**：通用的辅助代码。

| 文件 | 解释 |
| :--- | :--- |
| `CommonUtil.java` | 包含 MD5 加密、字符串判空、身份证校验等通用方法。就像一个“瑞士军刀”，哪里需要哪里搬。 |
| `UpdateDB.java` | 一个临时的工具类，用于在开发过程中修补数据库结构（比如之前我们加了余额字段）。 |

#### 3.2.6 过滤器 (`filter/`)
**作用**：拦截请求，进行统一处理。

| 文件 | 专业解释 | 通俗解释 |
| :--- | :--- | :--- |
| `AuthFilter.java` | 权限过滤器。拦截 `/patient/*` 和 `/admin/*` 等路径，检查 Session 中是否有登录用户。 | 医院内部的“安检门”。你想进特护病房（受保护页面），它先看你有没有通行证（是否登录）。没有就踢回大厅（登录页）。 |
| `CharacterEncodingFilter.java` | 字符编码过滤器。统一设置 Request/Response 编码为 UTF-8。 | “翻译官”。确保进出的数据都是中文 UTF-8 编码，防止出现乱码（天书）。 |

## 4. 常见问题与调试 (FAQ)

### Q1: 为什么页面报错 500？
- **通俗解释**：后端代码崩了。
- **排查**：看 IDEA/VS Code 的控制台输出（Stack Trace）。
    - `NullPointerException`: 空指针。通常是没登录就访问了页面，或者数据库查出来是空的。
    - `SQLException`: SQL 写错了，或者数据库连不上。

### Q2: 为什么页面报错 404？
- **通俗解释**：找不到路了。
- **排查**：
    - 检查 URL 拼写对不对。
    - 检查 `web.xml` 里 Servlet 的 `url-pattern` 映射对不对。
    - 检查 JSP 文件是不是真的在那个文件夹里。

### Q3: 为什么修改了 Java 代码没生效？
- **原因**：Java 是编译型语言，改了源码 (`.java`) 必须重新编译成字节码 (`.class`) 才能运行。
- **解决**：运行 `mvn clean package` 重新打包，或者重启 Tomcat。

### Q4: 为什么修改了 JSP 没生效？
- **原因**：浏览器缓存或者 Tomcat 缓存。
- **解决**：刷新浏览器（Ctrl+F5 强制刷新），或者等待几秒钟 Tomcat 自动热加载。

## 5. 总结

这个项目是一个非常标准的 Java Web 入门级项目。它没有使用复杂的框架（如 Spring Boot），而是使用了最基础的 Servlet + JSP。
**优点**：能让你透彻理解 Web 请求是如何从浏览器发给服务器，服务器又是如何处理并返回的。
**学习建议**：
1. 先看 `entity`，理解数据长什么样。
2. 再看 `dao`，理解数据怎么存取。
3. 接着看 `servlet`，理解请求怎么处理。
4. 最后看 `jsp`，理解数据怎么展示。
